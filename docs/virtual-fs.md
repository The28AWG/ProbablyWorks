# Файловая система виртуального хоста

Виртуальный Host держит три слоя. Они не связаны с синтаксисом оболочки: состав языка описан в [shell.md](shell.md).

## Слои

- **База.** Домашний каталог и всё, что агент создаёт вне `/tmp` и системных корней. Переживает перезапуск приложения. Владелец — `agent`, uid 1000.
- **Память процесса.** `/tmp` и всё внутри него. Каталог принадлежит `root`, режим `1777`. Файл, записанный одной командой, виден следующей, пока процесс приложения жив. Выгрузка процесса стирает каталог. Отдельного шага очистки нет.
- **Снимок.** `/bin`, `/usr`, `/etc`, `/proc`, `/root`. Не хранится и не входит в квоту. Запись, удаление, `chmod` и перенос дают `Read-only file system`. Одноимённая запись в базе под этим корнем не показывается.

Квота складывает байты базы и байты `/tmp`. Снимок в сумму не входит.

`cp` из снимка в `/tmp` или домой читает байты снимка и создаёт файл агента. `mv` между `/tmp` и базой переносит файл. Если запись не удалась, оба слоя возвращаются к прежнему состоянию.

## Команды

`/bin` содержит по файлу на каждый апплет и `/bin/sh`. Размер файла — 0: у апплета нет байтов, колонка размера равна длине содержимого. Режим `0711`: агент может выполнить команду и не может её прочитать. `cat /bin/ls` отвечает `Permission denied`. `test -s` для такой команды ложен.

`/usr/bin/<имя>` — симлинк на `/bin/<имя>`. `/usr/local/bin` пуст, он есть в `PATH`.

Запуск по-прежнему идёт через реестр апплетов, а не через содержимое файла. `/bin/sh` существует, чтобы `$SHELL` и `test -x` находили путь. Запуск `/bin/sh` отвергается: отдельного процесса оболочки нет, скрипты на виртуальном хосте не исполняются.

## Служебные файлы

`/etc/passwd`, `/etc/group`, `/etc/hostname` и `/etc/os-release` читаются. Имя хоста и пользователь берутся из профиля. Режим `0644`, владелец `root`.

`/proc` — небольшой набор: `version`, `uptime`, `loadavg`, `meminfo`, `cpuinfo`. `uptime` считается от создания хоста. Нагрузка — нули. Память и процессор — статичная картина виртуальной машины, не компьютера, где запущено приложение, и не дисковая квота.

Каталоги снимка — `0755`. Агент входит и читает список. `test -w` для них ложен: бит записи есть у root, а агент проверяется как «остальные».

`/root` пуст. Это домашний каталог root из `/etc/passwd`.
