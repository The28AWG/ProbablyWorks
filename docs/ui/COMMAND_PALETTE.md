# Единая палитра команд и поиска

**Статус:** частично реализовано. Связана с PW-020.
**Цель:** одна палитра для команд, плагинов и поиска по чатам, с нечётким
поиском, многоуровневыми командами и переназначаемыми горячими клавишами.

## 0. Что уже реализовано

- Единая палитра с поиском и деревом команд.
- Встроенные команды и группы.
- Серверный поиск чатов и сообщений.
- Фильтры `@command`, `@project`, `@current`, `@chat`, `@scope`.
- Fuzzy-поиск команд и мультиязычные названия.
- Плагинные команды и `PluginCommandHost`.
- Открытие по `Ctrl/Cmd+K` и переназначение клавиш в настройках.
- Кнопка «Назад» в дереве команд; неизвестный `@foo` остаётся текстом.
- Переход к сообщению из результата: открывается чат и прокручивается к нему.
- При открытии палитры выделение скрыто; первое движение стрелками только
  показывает его на текущей строке.
- «Назад» — полноценная строка дерева: её можно выбрать стрелками и Enter.
- Плагинный `openSettings({category})` открывает нужную группу настроек.
- Автоподсказки фильтров: оверлей у поля, список типов фильтров, проектов,
  чатов и областей поиска.
- Действия в системных уведомлениях: разрешить, отклонить, открыть чат.

## 1. UX

Пользователь открывает палитру горячей клавишей. Сверху поле поиска, ниже —
список. Пустой запрос показывает дерево команд. Ввод текста превращает дерево
в плоский список результатов: команды и чаты вперемешку, по точности
совпадения.

```text
┌──────────────────────────────────────────────┐
│  Поиск команд и чатов…                       │
├──────────────────────────────────────────────┤
│  ⚡ Новый чат                         Ctrl+N │
│  ⚙ Настройки                             ⌘,  │
│  📁 Проект → Память                         │
│  💬 Чат «Ревью состояния проекта»           │
│  💬 Чат «Настройка SSH»                     │
└──────────────────────────────────────────────┘
```

Состояния:

- пустой запрос — дерево команд, верхний уровень;
- ввод — смешанные результаты;
- поиск по чатам ещё идёт — строка загрузки, команды уже видны;
- ошибка поиска чатов — баннер, команды остаются доступны;
- нет результатов — `AppEmptyState`.

При открытии подсветка скрыта: логически выбрана первая строка, но
пользователь этого не видит. Первое нажатие `↓` показывает выделение на первой
строке, следующее — двигает вниз. Первое `↑` показывает последнюю строку.

Клавиатура:

- `↑`/`↓` — показать и переместить выбор;
- `Enter` — выполнить команду или открыть чат;
- `Enter`/клик на группе — войти в подменю;
- `Enter` на строке «Назад» — вернуться на уровень выше;
- `Esc` — назад, если открыта группа, иначе закрыть;
- мышь работает так же.

## 2. Модель команды

Команда и группа — один тип. Группа отличается отсутствием действия.

```dart
final class PaletteCommand {
  const PaletteCommand({
    required this.id,
    required this.titles,
    this.parentId,
    this.keywords = const LocalizedText(ru: '', en: ''),
    this.icon,
    this.action,
    this.order = 0,
    this.enabled = true,
  });

  final String id;
  final String? parentId;
  final LocalizedText titles;
  final LocalizedText keywords;
  final IconData? icon;
  final PaletteAction? action;
  final int order;
  final bool enabled;
}
```

`LocalizedText` хранит строки по языкам:

```dart
final class LocalizedText {
  const LocalizedText({required this.ru, required this.en, this.extra = const {}});
  final String ru;
  final String en;
  final Map<String, String> extra;
}
```

Для встроенных команд переводы берутся из ARB. Для плагинов — из их
локализации. Поиск индексирует все языки, показ — текущий.

Многоуровневость задаётся `parentId`. В дереве команда может быть на любом
уровне, в поиске она всегда плоская. В результате показывается путь:

```text
Проект → Память → Попросить ИИ поправить
```

## 3. Действия

Действие — не `VoidCallback` в модели, иначе модель нельзя использовать в
headless-части. Действие описывается типом:

```dart
sealed class PaletteAction {
  const PaletteAction();
}

final class BuiltinAction extends PaletteAction {
  const BuiltinAction(this.id);
  final String id;
}

final class PluginPaletteAction extends PaletteAction {
  const PluginPaletteAction(this.pluginId, this.commandId);
  final String pluginId;
  final String commandId;
}
```

`CommandDispatcher` в приложении знает `BuiltinAction.id` и вызывает нужный
код: открыть чат, создать чат, открыть настройки, сменить тему, перейти в
проект. Для плагинов диспетчер вызывает зарегистрированный обработчик.

Плагинам не нужен прямой доступ к `BuildContext`. Им даётся ограниченный
`PaletteHost`:

```dart
abstract interface class PaletteHost {
  Future<void> openChat(String chatId);
  Future<void> newChat({String? prompt});
  Future<void> openSettings();
  void notify(String message);
}
```

## 4. Реестр команд

`CommandRegistry` собирает команды из двух источников:

- встроенные команды приложения;
- `CommandPlugin` из `plugin_api`.

Плагинный интерфейс добавляется отдельно, чтобы не ломать существующий
`Plugin`:

```dart
abstract interface class CommandPlugin {
  String get id;
  Future<List<PluginPaletteCommand>> createCommands(PluginSettings settings);
}
```

`CommandRegistry`:

- проверяет уникальность `id`;
- проверяет, что `parentId` существует и нет циклов;
- сортирует по `order`, затем по локализованному названию;
- строит дерево и плоский список листьев;
- пересобирает индекс при регистрации/удалении плагина и смене языка.

## 5. Поиск команд

Поиск должен работать по смыслу названия, а не только по точному вхождению.
Предлагается трёхступенчатый скоринг.

### Нормализация

- нижний регистр;
- `ё` → `е`;
- удаление диакритики;
- пунктуация и лишние пробелы как разделители;
- разбиение на слова.

### Нечёткий поиск и стемминг — разные вещи

Это не одно и то же, и они решают разные задачи.

**Fuzzy / нечёткий поиск** — устойчивость к опечаткам и неполному вводу:

- `нстроки` находит `настройки`;
- `setings` находит `settings`;
- `конфиг` находит `конфигурация`.

Он сравнивает строки приблизительно: расстояние Левенштейна, Bitap (Fuse.js),
триграммы. Слово может быть написано с ошибкой, и это всё равно найдётся.

**Stemming** — приведение слова к основе, без учёта опечаток:

- `настройка`, `настройки`, `настроить` → `настро`;
- `setting`, `settings` → `set`.

Это помогает с формами слов и русской морфологией, но не с опечатками.

Для палитры приоритет — **fuzzy**: пользователь часто вводит сокращения и
ошибается. Stemming — дополнительный слой, если после тестов будет видно, что
формы слов мешают.

Варианты stemming:

- пакет `snowball_stemmer` (MIT, но давно не обновлялся);
- небольшой собственный стеммер для en/ru;
- явные корни/ключевые слова в описании команды.

Перед добавлением зависимости проверить версию, поддержку и уязвимости.

### Скоринг

Для каждого поля (название текущего языка, название другого языка, ключевые
слова):

1. точное совпадение — максимальный вес;
2. совпадение с началом слова — ниже;
3. вхождение подстроки — ещё ниже;
4. нечёткое совпадение (опечатки, пропуски) — ниже;
5. совпадение по стему — минимальный вес.

Текущий язык получает больший вес, чем второй. Ключевые слова весят меньше
названия. Для запросов короче 2 символов нечёткий поиск не включается.

Для нечёткости можно взять `fuse_dart` (порт Fuse.js, Bitap) или реализовать
триграммы/Левенштейна. Начать лучше с нормализации + префиксов + стема: этого
достаточно для палитры и не тянет зависимость.

## 6. Синтаксис фильтров

Строка поиска — одновременно текст запроса и фильтры. Фильтры разбираются на
клиенте и превращаются в параметры поиска.

```text
@command настройки
@current память
@current @command настройки
@project:"ProbablyWorks" миграция
@project:ProbablyWorks @chat:"Ревью" память
@scope:all @command проект
```

Поддерживаемые фильтры:

| Фильтр | Значение | Поведение |
| --- | --- | --- |
| `@command` | нет | Только команды. Серверный поиск чатов не выполняется |
| `@project:"Имя"` | имя или id | Поиск чатов только в этом проекте |
| `@project` | нет | Текущий проект открытого чата |
| `@current` | нет | Текущий открытый чат |
| `@current-project` | нет | Текущий проект открытого чата |
| `@chat:"Заголовок"` | заголовок или id | Поиск только в одном чате |
| `@scope:all` | `all` | Все чаты |
| `@scope:project` | `project` | Текущий проект |
| `@scope:chat` | `chat` | Текущий чат |

Правила:

- регистр фильтров не важен;
- значение с пробелами — в кавычках;
- `\"` внутри кавычек — экранированная кавычка;
- фильтры можно писать в любом месте строки;
- несколько фильтров комбинируются;
- `@command` отменяет серверный поиск, даже если рядом есть `@project`;
- `@current` работает, только если открыт чат; без открытого чата токен
  остаётся обычным текстом;
- `@current` — короткая форма `@scope:chat` для текущего чата;
- явный `@chat:"..."` важнее `@current`;
- `@current` и `@project` с другим проектом не дают отдельного пояснения:
  серверный поиск просто может вернуть пусто;
- неприменимый фильтр — неизвестное имя, неверный scope, отсутствующий
  проект или чат — остаётся обычным текстом запроса;
- канонические имена английские, но поддерживаются алиасы `@команда`,
  `@проект`, `@чат`, `@текущий`, `@текущий-проект`.

Результат разбора:

```dart
final class PaletteQuery {
  const PaletteQuery({
    required this.text,
    required this.commandsOnly,
    required this.scope,
    this.projectId,
    this.chatId,
    this.currentChat = false,
  });

  final String text;
  final bool commandsOnly;
  final SearchScope scope;
  final String? projectId;
  final String? chatId;

  /// `@current` или `@scope:chat` без явного `@chat`.
  final bool currentChat;
}
```

### Проект: имя или id

Клиент уже знает список проектов. Поэтому `@project:"Имя"` сначала
разрешается в `projectId` на клиенте:

- точное совпадение по id или имени — фильтр применяется, на сервер уходит
  `projectId`;
- несколько совпадений или ничего не найдено — фильтр не применяется, токен
  возвращается в текст запроса и ищется как обычное слово.

Ошибок и отдельных пустых состояний из-за имени проекта нет: пользователь
просто видит результаты обычного поиска. То же самое для `@chat:"..."`.

Команды остаются глобальными: `@project` ограничивает только чаты. Если нужны
только команды, используется `@command`.

### Подсказки при вводе

Подсказки — оверлей у поля поиска, а не `PopupMenu` и не `DropdownButton`.
Так проще удержать дизайн: ширина, отступы и обрезка текста задаются явно.

- ввод `@` показывает типы фильтров;
- продолжение имени (`@pro`) сужает список типов;
- `@project:` показывает проекты с fuzzy-подбором по имени; если список
  проектов пришёл позже, подсказки обновляются без переоткрытия палитры;
- `@chat:` показывает чаты;
- `@scope:` показывает `all`, `project`, `chat`;
- `@command`, `@current`, `@current-project` вставляются без значения;
- выбранный тип с двоеточием (`@project:`) сразу открывает список значений.

Геометрия:

- ширина оверлея равна ширине поля:
  `min(AppLayout.formMaxWidth, screenWidth - 2*AppSpacing.lg) - 2*AppSpacing.lg`;
- позиция — от левого нижнего угла поля через
  `OverlayPortal.overlayChildLayoutBuilder`: он даёт надёжную paint-матрицу
  поля и не ломает вложенные `Tooltip`;
- высота ограничена и список прокручивается;
- каждая строка — одна строка текста с `TextOverflow.ellipsis`; полный текст
  виден в `Tooltip`;
- оверлей не выходит за поле по горизонтали и не расширяет диалог.

Управление:

- `↑`/`↓` — выбор подсказки; список прокручивается так, чтобы выбранная
  строка всегда была видна целиком;
- `Enter` или `Tab` — вставить;
- `Esc` — закрыть подсказки, палитра остаётся открытой;
- на телефоне — тап по строке;
- тап вне поля и оверлея закрывает подсказки.

Фильтры не выделяются чипами: строка поиска остаётся единственным местом,
где виден запрос. Работающий фильтр влияет на поиск, неработающий ничем не
отличается от обычного текста.

### Влияние на поиск

- `@command` — локальный fuzzy-поиск только по командам;
- `@current` — локальные команды + серверный поиск в открытом чате;
- `@project` — локальные команды + серверный поиск чатов в проекте;
- `@chat` — локальные команды + серверный поиск в одном чате;
- `@scope:all` — локальные команды + серверный поиск по всем чатам;
- свободный текст без фильтров — текущая область по умолчанию.

## 7. Поиск по чатам

Поиск по чатам выполняется **на сервере**, не на клиенте. Клиент не должен
читать всю историю для палитры.

Новый порт:

```dart
enum SearchScope { chat, project, all }

final class SearchQuery {
  const SearchQuery({
    required this.text,
    required this.scope,
    this.projectId,
    this.chatId,
    this.limit = 20,
  });
}

final class SearchHit {
  const SearchHit({
    required this.kind,
    required this.title,
    required this.score,
    this.chatId,
    this.chatTitle,
    this.projectId,
    this.messageId,
    this.seq,
    this.snippet,
  });
}

// Метод добавлен в AgentApi, чтобы локальный и удалённый клиент
// использовали один контракт.
Future<List<SearchHit>> search(SearchQuery query);
```

Серверный endpoint:

```text
GET /api/v1/search?q=...&scope=chat|project|all&projectId=...&chatId=...&limit=...
```

Сервер:

- ищет сообщения через `ChatRepository.searchMessagesAll`;
- ищет названия чатов;
- возвращает сниппет, chatId, chatTitle, messageId, seq, projectId;
- не отдаёт сырой transcript;
- не возвращает tool/event-сообщения: у них нет строки в ленте;
- соблюдает лимит результатов.

Клиент объединяет серверные результаты с командами по нормализованному score.
Команды и чаты получают тип в строке (`команда`, `чат`, `сообщение`).

## 8. Горячие клавиши

Переназначение реализовано.

### Модель

```dart
final class Keybinding {
  const Keybinding({
    required this.key,
    this.control = false,
    this.meta = false,
    this.shift = false,
    this.alt = false,
  });

  final LogicalKeyboardKey key;
  final bool control;
  final bool meta;
  final bool shift;
  final bool alt;
}
```

Есть `label`, `encode`/`decode` и `matches(KeyEvent)`. Основная клавиша одна;
сочетания вроде `Ctrl+Shift+N` задаются модификаторами.

Действия:

- `palette.open` — открыть палитру;
- `chat.new` — новый чат;
- `settings.open` — настройки.

### Хранение

Клиентская настройка `keybindings` в `ClientSettings`:

```json
{
  "palette.open": "ctrl+k",
  "chat.new": "ctrl+shift+n",
  "settings.open": "ctrl+comma"
}
```

Это настройка устройства, а не профиля агента. На macOS по умолчанию
используется `Cmd`, на Linux/Windows — `Ctrl`.

### Применение

- `KeybindingService` загружает overrides и отдаёт `bindingFor(actionId)`;
- `CommandPaletteHost` держит глобальный `HardwareKeyboard` handler и
  вызывает `actionFor(event)`;
- при открытом диалоге или чужом маршруте глобальные действия не срабатывают;
- конфликт проверяется до сохранения: два действия не могут делить одно
  сочетание;
- сброс возвращает default, но тоже проверяет конфликт.

### Настройки

Секция «Горячие клавиши» находится в «Продвинутых»:

- список действий;
- текущее сочетание на кнопке;
- нажатие открывает запись: следующая клавиша становится сочетанием;
- `Esc` отменяет запись;
- конфликт показывается snackbar и не сохраняется;
- кнопка сброса возвращает default.

## 10. Этапы

1. **Каркас палитры:** модель, реестр, встроенные команды, окно,
   открытие по `Ctrl/Cmd+K` — готово.
2. **Поиск по командам:** нормализация, префиксы, fuzzy, мультиязычность,
   фильтры — готово.
3. **Серверный поиск чатов:** `AgentApi.search`, endpoint, объединение
   результатов — готово.
4. **Плагинные команды:** `CommandPlugin`, `PluginCommand`,
   `PluginCommandHost`, `CommandPluginRegistry` — структура готова.
5. **Горячие клавиши:** сервис, настройки, запись и конфликты — готово.
6. **Переход к сообщению:** `message` в маршруте, прокрутка и подсветка —
   готово.
7. **Автоподсказки фильтров:** оверлей у поля, типы, проекты, чаты, scope —
   готово.
8. **Stemming:** не добавлен; fuzzy и префиксов пока достаточно.
9. **Действия в уведомлениях:** approve/deny/open, payload и обработка
   запуска приложения — готово.

## 11. Решения и остаток

Принятые решения:

- основное сочетание — `Ctrl/Cmd+K`;
- пустой запрос показывает дерево команд, без недавних чатов;
- ищутся и названия чатов, и сообщения;
- `@current` без открытого чата показывает подсказку, без fallback;
- неизвестный `@foo` остаётся обычным текстом;
- плагины получают `openChat`, `newChat`, `openSettings(category)` и
  `notify`; свободного `sendPrompt` нет;
- stemming отложен.

PW-020 закрыт. Стемминг остаётся возможным улучшением, но не обязательным:
fuzzy и префиксов хватает для текущих названий команд.

## 12. Действия в уведомлениях

Уведомление о карточке подтверждения получает кнопки. Остальные события
(вопрос, завершение, ошибка, лимит шагов, фоновая команда) открываются
нажатием на само уведомление.

Платформы:

- Android, iOS, macOS — кнопки «Разрешить» и «Отклонить»; нажатие на
  уведомление открывает чат;
- Linux и Windows — только открытие: action-кнопок в текущей версии
  `flutter_local_notifications` нет.

Payload:

```json
{
  "profileId": "p-...",
  "chatId": "c-...",
  "approvalId": "a-..."
}
```

Поведение:

- approve вызывает `resolveApproval(id, allowOnce)`, deny — `deny`;
  разрешение «на ход» и «на чат» из уведомления не выдаётся;
- approve/deny работают через API профиля: локальный агент, локальный
  демон или удалённый сервер;
- если карточка уже исчезла или запрос не прошёл, действие открывает чат:
  пользователь увидит актуальное состояние;
- если приложение запущено нажатием на кнопку, ответ забирается из
  `getNotificationAppLaunchDetails` после инициализации плагина;
- если действие пришло раньше, чем bootstrap подключил обработчик, оно
  запоминается и выполняется после регистрации;
- уведомление из встроенного агента не знает `profileId` — используется
  локальный профиль.

```text

lib/core/notify/app_notifier_plugin.dart
lib/app/notifications/notification_action_service.dart
lib/app/bootstrap/bootstrap.dart
```
