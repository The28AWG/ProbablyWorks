# Локальные модели (llamadart)

Среда выполнения локальных моделей: файлы `GGUF` на диске, их параметры и
движок в памяти процесса. Провайдер `llamadart` — тонкая вьюха над средой,
поэтому выключение провайдера не мешает скачивать, настраивать и удалять
файлы.

## Два разных понятия

| | Модель среды выполнения | Модель провайдера |
| --- | --- | --- |
| Что это | файл `GGUF` + параметры запуска | нейросеть в общем каталоге |
| Где живёт | `LocalModelsService` | адаптер `LlmProvider` |
| Идентификатор | короткий хеш источника (`a1b2c3d4e5f6a7b8`) | `llamadart:<id>` |
| Пример | `qwen3-4b-q4_k_m.gguf` | `llamadart:a1b2c3d4e5f6a7b8` |

Файл может не дать ни одной модели провайдера (например, файл эмбеддингов или
модель без шаблона инструментов). Провайдер может отдавать модели, файлами
которых среда не управляет (llama.cpp server). Поэтому это разные слои.

## Ключевые файлы

- `packages/pw_agent/lib/providers/ai/local_models.dart` — доменные типы,
  `LocalModelsSource`, `LocalModelRuntime`;
- `packages/pw_agent/lib/providers/ai/llamadart/local_models_service.dart` —
  среда: файлы, параметры, движок, очередь, авто-выгрузка;
- `packages/pw_agent/lib/providers/ai/llamadart/local_engine.dart` — мост к
  llamadart (`LlamaEngine`, сообщения, инструменты, события порта);
- `packages/pw_agent/lib/providers/ai/llamadart/local_storage.dart` — кэш
  загрузок поверх `DefaultModelDownloadManager`;
- `packages/pw_agent/lib/providers/ai/llamadart/llamadart_llm_provider.dart` —
  провайдер `LlmProvider` + `LlmModelRuntimeProvider`;
- `packages/pw_agent/lib/core/data/local_model_repository.dart` — таблица
  `local_models`;
- `lib/features/settings/presentation/widgets/local_models_section.dart` —
  раздел настроек «Локальные модели».

## Что умеет среда

- **Файлы:** скачивание по `hf://`, HTTP(S) или локальному пути, импорт
  готового файла, удаление, очистка кэша, занятое место. Файлы лежат в
  `<support>/models` — вне системного кэша, чтобы ОС не удалила гигабайты.
- **Параметры файла:** контекст, слои GPU, потоки, батч, mmap, лимит токенов,
  температура, top-p/top-k/min-p, штрафы, стоп-последовательности, бюджет
  рассуждений, вызов инструментов и мультимодальный проектор (`mmproj`).
- **Мультимодальность:** если у модели задан проектор, провайдер объявляет
  `text` и `image`, а llamadart загружает модель и проектор одной операцией.
  Аудио добавляется только при включённом флаге «Проектор понимает аудио»:
  большинство `mmproj` визуальные, и лишняя модальность приводила бы к ошибке.
  Проектор скачивается при первой загрузке в память (путь, `hf://` или
  HTTP(S)); без проектора модель текстовая.
- **Движок:** одна модель в памяти, `load`/`unload`, авто-выгрузка по простою.
- **Очередь:** FIFO. Пока запрос ждёт, адаптер раз в 20 секунд отдаёт пустую
  дельту — так watchdog агента не считает ожидание зависанием.

## Состояние памяти и провайдер

Пока файлов нет, карточка провайдера подсказывает открыть раздел «Модели»,
а не показывает «провайдер не ответил».

Провайдер реализует `LlmModelRuntimeProvider`:

- `snapshotRuntime`/`watchRuntime` — `unloaded`, `loading`, `loaded`,
  `unloading`, `failed` по каждому установленному файлу; при скачивании
  проектора `loading` несёт долю прогресса;
- `loadRuntimeModel`/`unloadRuntimeModel` — команды среде;
- `runtimeEnabled` — включённость провайдера. Выключенный провайдер не
  опрашивается, но раздел «Локальные модели» продолжает работать.

Скачивание файла модели в `/models/runtime` не попадает: это файл, а не
память. Оно видно в снимке среды (`/models/files`) и в SSE-событии
`localModels`. Скачивание проектора происходит при загрузке в память и
показывается как `loading` с долей прогресса.

## Фоновые загрузки на телефоне

На desktop и в демоне файлы качает Dart-менеджер llamadart: `.part`,
проверка SHA-256, докачка после обрыва. На Android и iOS используется
`BackgroundLocalStorage` поверх `background_downloader`:

- iOS — background `URLSession`: загрузка продолжается, когда приложение
  свёрнуто или завершено; система поднимает приложение для обработки
  результата;
- Android — WorkManager (на Android 14+ UIDT): задача переживает фон и смерть
  процесса; длинная загрузка обходится `TransferHint.largeFile` (пауза и
  автопродолжение между 9-минутными циклами WorkManager);
- прогресс и уведомление рисует ОС: Android — с progress bar и кнопками
  паузы/отмены, iOS — одно уведомление о ходе и завершении **без progress bar**
  (Apple его не поддерживает);
- путь — `BaseDirectory.applicationSupport` + `ProbablyWorks/models`, то есть
  тот же `AppPaths.models`; `list` сканирует каталог, поэтому переезд
  контейнера на iOS не ломает путь;
- токен Hugging Face уходит в `headers` задачи; после завершения запись задачи
  удаляется, и токен исчезает из базы загрузчика. Это приватное хранилище
  ОС/плагина, не наша БД и не логи; для таких токенов лучше использовать
  read-only/repo-scoped токен. Подробнее — в [SECURITY.md](SECURITY.md).

### Очередь после перезапуска

Активные задания хранятся в таблице `local_model_downloads` (`id` = `taskId`):
источник, имя, sha256, время. Прогресс в БД не пишется — байты уже в `.part`
или в платформенной задаче. При старте `LocalModelsService` читает задания и
заново вызывает `storage.ensure` с тем же `id`:

- Dart-менеджер докачивает `.part` (нужен ETag/Last-Modified для `If-Range`;
  Hugging Face его отдаёт);
- платформенный загрузчик подхватывает существующую задачу через
  `Transfers.getOrStart` и продолжает её, даже если приложение было закрыто;
- устаревшее задание (модель уже установлена) удаляется;
- успех, отмена и ошибка удаляют задание; ошибка показывается баннером.

`POST /models/files/install` возвращает id сразу, поэтому HTTP-запрос не
висит всё скачивание; прогресс идёт через SSE `localModels`.

## API

```text
GET    /api/v1/models/files                  снимок среды
POST   /api/v1/models/files/install          {"source": "...", "name": null, "sha256": null}
                                             → {"id": "..."} сразу, скачивание идёт в фоне
POST   /api/v1/models/files/import           {"path": "...", "name": null}
POST   /api/v1/models/files/cancel           {"id": "..."}
PATCH  /api/v1/models/files/{id}             {"settings": {...}}
DELETE /api/v1/models/files/{id}
POST   /api/v1/models/files/clear
PUT    /api/v1/models/files/auto-unload      {"minutes": 0}
```

Установка не держит HTTP-запрос открытым: сервер возвращает id, а прогресс,
завершение и ошибки приходят в SSE-событии `localModels`. Снимок также доступен
в `GET /models/files`. Загрузка в память идёт прежними маршрутами
`/models/runtime/load|unload`.

## Секреты

Токен Hugging Face для закрытых репозиториев хранится в `SecretStore` под
ключом `huggingface.token`. Переменные окружения:
`PROBABLY_WORKS_HUGGINGFACE_TOKEN` и `HF_TOKEN`. В настройках провайдера его
нет: это секрет среды, а не ключ провайдера.

## Платформы и упаковка

llamadart несёт предсобранные рантаймы llama.cpp через build hooks. В
`pubspec.yaml` корня workspace включён только `llama_cpp`:

```yaml
hooks:
  user_defines:
    llamadart:
      llamadart_native_runtimes: [llama_cpp]
```

Следствия:

- первый `dart run`, `dart test`, `flutter build` скачивает архив рантайма и
  кэширует его в `.dart_tool/hooks_runner` и `~/.pub-cache/.../.dart_tool`;
- демон собирается тем же `dart build cli`, поэтому библиотеки попадают в
  `daemon/lib` автоматически;
- на macOS и iOS нужны companion-пакеты `llamadart_*_flutter` и минимальные
  версии ОС: iOS 16.4, macOS 14.0;
- на macOS x86_64 GPU-путь отключён (Metal даёт некорректный вывод), модель
  идёт на CPU.

## Ограничения

- Одна генерация за раз. Параллельные запросы ждут в очереди; отмена
  активного запроса останавливает движок, отмена ждущего — только убирает его
  из очереди.
- Мультимодальность требует совместимого `mmproj.gguf`. Изображения
  объявляются всегда при наличии проектора; аудио — только по флагу в
  параметрах модели. Неподходящий файл вернёт `LlmFailure` при загрузке или
  генерации, проектор можно убрать в параметрах.
- Смена параметров загрузки применяется при следующей загрузке в память.
- Импортированный файл принадлежит пользователю: удаление записи не удаляет
  файл с диска.
- Нативное падение llama.cpp завершает процесс. Для удалённого сервера
  безопаснее внешний `llama-server` и провайдер `llamacpp:`.
- iOS: уведомление без progress bar; background-загрузка ограничена системным
  resource timeout (по умолчанию 4 часа). Если пользователь принудительно
  закрыл приложение из App Switcher, система может оборвать задачу.
- Android: на Android 13+ нужно разрешение на уведомления (запрашивается при
  первой загрузке); на Android 15 у dataSync/UIDT есть лимит времени, после
  которого задача останавливается и докачивается при следующем запуске.
