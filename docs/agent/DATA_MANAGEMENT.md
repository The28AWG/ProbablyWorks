# Очистка истории и сброс настроек

Раздел **Настройки → Данные** управляет необратимыми операциями профиля:
очисткой истории чатов и сбросом предпочтений. Экспорт и импорт настроек и
истории — следующий шаг; в текущей версии их нет.

Карточка «Занятое место» считает задачи планировщика отдельно по статусам:
запланированные (`pending`), выполненные (`dispatched`), с ошибкой и
отменённые. Выполненная задача — та, чьё сообщение уже передано сессии;
дальнейший ход и его результат видны в журнале чата.

## Что удаляет очистка истории

Очистка удаляет обычные чаты и все их скрытые чаты субагентов. Для каждого
чата уходят:

- сообщения, запуски инструментов, ревизии состояния и запланированные задачи
  (каскадом внешних ключей);
- строки FTS-индекса `message_search`;
- пер-чатовые ключи настроек: дневной лимит, расход по дням и метаданные
  сжатия;
- файлы логов запусков и снимки ходов в каталоге `chats/`.

Проект, в котором не осталось чатов, уходит в архив по обычным правилам и
удаляется через неделю. Хосты, настройки, MCP-серверы, профили политики,
локальные модели, секреты и память проектов не затрагиваются.

Очистка бывает двух видов:

- **все чаты** — удаляются все видимые чаты профиля;
- **старше N дней** — удаляются чаты, у которых `updatedAt` старше срока.
  Скрытые субагенты удаляются вместе с родителем, даже если обновлялись позже.

Перед удалением идущий ход останавливается. Если открытый в соседней вкладке
чат попал под очистку, его маршрут заменяется стартовым экраном: возвращаться
на удалённую запись нельзя. После удаления SQLite выполняет `VACUUM`:
страницы удалённых строк возвращаются файлу базы, а размер в карточке
пересчитывается. Если сжать базу не удалось, результат очистки предупреждает
об этом, а место останется до следующей успешной очистки. Операция необратима,
поэтому интерфейс показывает число чатов и сообщений и требует подтверждения.

## Что сбрасывает сброс настроек

Сброс возвращает значения по умолчанию для предпочтений агента и интерфейса:

- модели по умолчанию, заголовков, памяти, субагентов и запасная;
- уровни рассуждений, политику, denylist, уровни безопасности и лимиты;
- закреплённые модели и отображение журнала шагов;
- адреса и включённость провайдеров (`provider.<id>.*`, старые ключи
  `llamaCpp.*`);
- язык, тему, ширину боковой панели, горячие клавиши и сортировку моделей.

Не затрагиваются: ключи и пароли в `SecretStore`, хосты, чаты, проекты и их
память, MCP-серверы, профили политики, локальные модели и их файлы, дневные
расходы чатов и одноразовые флаги миграций.

Сброс доступен в трёх вариантах: только агент, только интерфейс или оба.
Интерфейс применяет язык и тему сразу; остальные клиентские значения
читаются при следующем обращении. Когда агент offline, раздел «Данные»
показывает только сброс интерфейса: история и настройки агента недоступны.

## API

Контракт живёт в `packages/pw_agent/lib/agent/api/data_api.dart`:

```dart
abstract interface class DataApi {
  Future<DataUsage> usage();
  Future<HistoryClearResult> clearHistory({int? olderThanDays});
  Future<void> resetSettings();
}
```

Локальная реализация (`LocalDataApi`) работает с SQLite и каталогом данных
напрямую. Удалённый профиль вызывает HTTP API:

- `GET /api/v1/data/usage`;
- `POST /api/v1/data/history/clear` с телом `{"olderThanDays": 30}` или `{}`;
- `POST /api/v1/data/settings/reset`.

Удаление чатов идёт через `ChatDeletionService` — тот же путь, что и удаление
одного чата из списка. Поэтому логи и снимки файлов не остаются сиротами.
