# Упоминания файлов в чате

`@` в поле ввода открывает список файлов и каталогов проекта. Это не вложение:
в контекст модели уходит путь, а не содержимое. Содержимое агент читает сам
инструментами `read_file`, `list_dir`, `glob` и `grep`.

## Отображение и полный путь

Пользователь видит только последний сегмент пути:

```text
@app.dart
@"файл с пробелами.txt"
@features/
```

Полный путь хранится рядом с текстом в `MentionRef` как диапазон UTF-16. В
контексте модели диапазон заменяется на путь относительно workspace:

```text
текст:   Смотри @app.dart
ref:     {path: "src/app.dart", start: 7, end: 16}
модель:  Смотри @src/app.dart
```

Поэтому два `@app.dart` из разных каталогов не путаются, а редактирование
текста не заставляет угадывать файл по имени.

`MentionRef` живёт в черновике, правках сообщений, сообщениях и очереди. Для
основного черновика добавлена колонка `draft_mentions` (schema v23), сообщения
хранят диапазоны в JSON payload.

## Что считается упоминанием

- Упоминание создаётся только явным выбором из списка. Набранный вручную
  `@app.dart` остаётся обычным текстом, пока пользователь не выберет файл.
- Список открывается для любого `@`-токена под кареткой, включая вставленный
  из буфера текст. Выбор заменяет существующее упоминание или добавляет новое.
- На десктопе список можно открыть повторно по `Ctrl+Space` (по умолчанию),
  даже если он был закрыт кликом или `Esc`, а каретка осталась в токене.
  Сочетание переназначается в настройках горячих клавиш.
- Открытие списка, `Esc`, клик вне и повторный выбор того же пути упоминание не
  сбрасывают. Выбор другого пути заменяет только `MentionRef.path`.
- Изменение текста внутри токена удаляет упоминание. Возврат текста через undo
  или повторный ввод не восстанавливает путь: нужно снова выбрать файл.

## Поиск

Поиск выполняется по проекту, а не по произвольному пути из запроса:

```text
GET /api/v1/projects/{projectId}/mentions?q=rdm
```

Для незаписанного чата сначала ищется существующий проект по паре «хост +
папка»:

```text
GET /api/v1/projects/lookup?hostId=...&workspace=...
```

Lookup не создаёт проект и не сканирует файлы. Если проекта нет, подсказки не
открываются: в этот момент сканирование workspace недоступно.

В запросе нет `depth`, `limit` и `timeout`. Глубину, число результатов,
таймаут и способ обхода выбирает агент. Это не позволяет клиенту заказать
обход глубины 100000 или неограниченный ответ. Поиск идёт по подпоследовательности
имени: `rdm` находит `README.md`; скрытые файлы показываются только при запросе,
начинающемся с `.` (или содержащем `/.`). Шумовые каталоги (`.git`,
`node_modules`, `build` и т.п.) не обходятся.

Глубина ограничена шестью уровнями, пустой запрос показывает только верхние
уровни. Это осознанный компромисс: один запрос не должен занимать минуты на
огромном workspace. Для git-репозиториев в будущем можно добавить отдельный
быстрый путь через `git ls-files`, не меняя клиентский контракт.

## Редактирование

`MentionTextController` хранит текст и диапазоны. При правке:

- вставка до/после упоминания сдвигает диапазон;
- правка внутри токена удаляет упоминание;
- буква, цифра, `.`, `_`, `-`, `/` в конце токена считаются продолжением имени
  и удаляют упоминание;
- пробел, запятая и другая пунктуация после токена упоминание сохраняют;
- загрузка черновика не открывает список сама по себе.

## Ограничения

- Копирование/вставка переносит только видимый текст, без метаданных.
- Undo/redo может вернуть текст без упоминания.
- Для правки и удаления сообщения диапазоны пересчитываются тем же контроллером.
