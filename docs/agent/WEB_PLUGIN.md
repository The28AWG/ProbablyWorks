# Плагин «Веб»: поиск и сбор данных со страниц

Статус: **реализован** как встроенный плагин `web`. Ядро — чистый Dart,
представление — отдельный Flutter-пакет. Плагин выключен по умолчанию.

Документ объясняет, как устроен плагин, что он хранит, что выбрасывает и
почему. Это не описание будущих вариантов: ниже — фактическое поведение
кода.

## 1. Что делает плагин

Плагин даёт модели четыре инструмента:

| Инструмент | Назначение |
|---|---|
| `plugin_web_search` | найти страницы по запросу |
| `plugin_web_open` | открыть страницу и получить читаемый текст |
| `plugin_web_read` | прочитать открытую страницу: chunk, grep, outline |
| `plugin_web_extract` | собрать записи по CSS-селекторам |

Все инструменты read-only: `mutatesHost = false`. Плагин не пишет файлы, не
запускает команды и не меняет Host. Если результат нужно сохранить, модель
использует обычный `write_file`.

Плагин не делает:

- логин, cookies и приватные сессии;
- обход CAPTCHA и paywall;
- клики, формы и визуальный анализ;
- скачивание файлов;
- парсинг поисковой выдачи HTML-скрапингом;
- произвольный JavaScript на странице.

## 2. Конвейер страницы

```text
HTTPS → декодирование → DOM → очистка → нормализация → снимок
                                              ↓
                                    read / grep / outline
                                              ↓
                                          extract
```

1. **Загрузка.** `PageFetcher` идёт только через `PluginHost.httpRequest`:
   приложение проверяет HTTPS, адрес назначения и подставляет секреты.
2. **Кодировка.** Сначала charset из `Content-Type`, затем `<meta charset>`,
   затем UTF-8 с `allowMalformed`. Сырые байты нужны потому, что `http`
   без charset по умолчанию использует latin1.
3. **Очистка.** Удаляются `script`, `style`, `noscript`, `template`, `svg`,
   `canvas`, `iframe`, `form`, `button`, `input`, `select`, `textarea`, `nav`,
   `footer`, `aside`, ARIA-навигация и скрытые элементы. У элементов
   удаляются `style`, `srcset`, `sizes` и обработчики `on*`.
4. **Нормализация.** Заголовки, параграфы, списки, таблицы, код, ссылки и
   изображения превращаются в Markdown. Одновременно собирается оглавление
   со смещениями в символах.
5. **Снимок.** В памяти остаётся нормализованный документ и очищенный DOM.
   Сырой HTML и CSS-стили не хранятся.

### Почему очистка до хранения

Модели нужны текстовые данные и структура, а не внешний вид. Если хранить
сырой HTML, он занимает в разы больше памяти, раздувает контекст и повышает
риск prompt injection. Поэтому в снимок попадают только текст, оглавление и
семантическое дерево.

При этом очистка **не разрушающая**: сохраняются заголовки, списки, таблицы,
`href`, `src`, `alt`, `class`, `id`, `data-*`, `aria-*` и `role`. Без этого
`extract` по CSS-селекторам потерял бы смысл. Очищенный DOM нужен только для
`extract`; чтение и grep работают по Markdown-тексту.

## 3. Что хранится, а что выбрасывается

| Данные | Хранится | Почему |
|---|---|---|
| Markdown-текст | Да | Источник истины для `read`, `grep`, `outline` |
| Оглавление и смещения | Да | Позволяет читать страницу частями без повторной загрузки |
| Очищенный DOM | Да, на время жизни снимка | Нужен для `extract` по селекторам |
| Метаданные (URL, title, lang, дата) | Да | Цитаты и воспроизводимость |
| Сырой HTML | Нет | Тяжёлый, не нужен модели, лишний риск |
| CSS, стили, раскладка | Нет | Не относятся к текстовым данным |
| Скрипты и обработчики | Нет | Не выполняются и не нужны |
| Cookie и заголовки авторизации | Нет | Плагин не работает с приватными сессиями |
| Картинки | Нет, только `alt` и ссылка | Визуальный анализ не входит в задачу |

Снимок живёт в `WebPageStore`: не больше 8 страниц на чат, 32 страниц на
процесс, 2 млн символов текста и 16 МБ очищенного DOM. Вытеснение — LRU,
TTL — 30 минут. Перезапуск приложения очищает кэш. Это осознанно: страница
нужна для нескольких чтений в рамках работы, а не как постоянный архив.

`page_id` непредсказуем и привязан к чату: прочитать чужую страницу по id
нельзя.

## 4. Инструменты

### `search`

Возвращает нумерованный список. Номер — это `ref`, который можно передать в
`open` или `extract`, не повторяя URL.

```text
query: VPS Германия цена
provider: brave
results: 2

[1] Название
    url: https://example.com/vps
    published: 2026-11-10
    snippet: ...
```

`search` создаётся только если провайдер настроен и ключ сохранён (для
SearXNG ключ не нужен). Без этого инструмент отсутствует, а `open` и
`extract` продолжают работать.

### `open`

Открывает URL, `ref` из последнего поиска или уже сохранённый `page_id`.
Режимы: `article`, `main`, `full`, `selector`, `links`, `tables`.

Возвращает заголовок с `page_id`, метаданными, оглавлением, `chars`,
`offset` и `next_offset`, затем порцию Markdown.

Если `open` вызывается с `page_id`, страница перерисовывается в другом
режиме без повторной загрузки. Это позволяет сначала прочитать статью, а
потом попросить таблицы.

### `read`

Работает только по `page_id` и не ходит в сеть:

- `chunk` — окно символов с `offset` и `limit`;
- `grep` — поиск по строкам, с контекстом, номерами строк и смещениями;
- `outline` — заголовки со смещениями.

`grep` по умолчанию ищет литерал без учёта регистра; `regex=true` включает
регулярное выражение. Длина шаблона ограничена, результаты и вывод обрезаются.

### `extract`

Собирает записи по очищенному DOM:

```json
{
  "page_id": "p_...",
  "container": ".plan",
  "fields": {
    "name": ".name",
    "price": ".price",
    "link": "a@href"
  }
}
```

Поле без `@` берёт текст, `selector@attr` — атрибут. Относительные ссылки
разрешаются относительно финального URL. Результат — JSON с `count`,
`offset`, `returned`, `truncated` и `records`. Не больше 100 записей и 20 000
символов за вызов.

## 5. Настройки и секреты

Настройки хранятся в kv как `pluginSettings.web` и не содержат ключей.

Провайдеры:

- **Brave** — `X-Subscription-Token`, ключ;
- **Tavily** — `Authorization: Bearer`, ключ;
- **SearXNG** — self-hosted инстанс с JSON API, без ключа.

Ключ записывается через write-only API `PluginSettings.writeSecret` в
`SecretStore` под ключом `plugin.web.secret.searchKey`. В настройках лежит
только ссылка `${secret:plugin.web.secret.searchKey}`. Прочитать значение
обратно через API нельзя.

Остальные настройки: количество результатов, безопасный поиск, язык,
максимум байтов и символов, таймаут, User-Agent, `robots.txt`, TTL кэша,
allow/deny домены.

## 6. Безопасность

- **Сеть только через Host.** Плагин не импортирует `dart:io` для HTTP и не
  получает прямой доступ к сокетам.
- **SSRF.** Для страниц выключены loopback и приватная сеть; каждый редирект
  проверяется отдельно. Хост резолвит DNS и отклоняет приватные, link-local,
  multicast и loopback адреса.
- **Редиректы.** Плагин выключает автоматические редиректы, проверяет
  `Location`, схему, домен и `robots.txt` для каждого шага; не больше 5.
- **robots.txt.** Учитывается по умолчанию, с кэшем на час. Ошибка загрузки
  `robots.txt` не блокирует страницу.
- **Недоверенный вывод.** `ContextBuilder` оборачивает `plugin_*` и `mcp_*`
  в `<untrusted>`: содержимое страницы — данные, а не инструкции.
- **Подтверждения.** Инструменты проходят общий `PolicyEngine` и карточку
  approve. Разрешение на домен можно выдать на текущий ход; `read` по
  локальному снимку уже не сетевой запрос.
- **Домены.** Deny сильнее allow; пустой allow означает все домены.
- **Секреты.** Ключ не попадает в SQLite, логи, контекст и сообщения ошибок.
- **Лимиты.** Размер ответа, таймаут, количество записей и символов
  ограничены; тело сверх лимита не сохраняется.

## 7. Ошибки

Ошибки типизированы и имеют стабильный код: `bad_url`, `bad_arguments`,
`domain_blocked`, `robots_disallowed`, `access_denied`, `not_found`,
`rate_limited`, `response_too_large`, `unsupported_content_type`,
`page_requires_javascript`, `extraction_empty`, `selector_matched_nothing`,
`page_expired`, `unknown_ref`, `not_html`, `search_not_configured`,
`provider_auth_failed`, `provider_rate_limited`, `provider_unavailable`,
`provider_bad_response`.

Формат:

```text
error: <code>
message: <что случилось>
hint: <что попробовать>
```

## 8. Будущий рендерер

В конфигурации есть поле `renderer`, сейчас всегда `none`. Если появится
браузерный рендер, он будет ещё одним источником HTML: сначала рендер, потом
та же очистка, нормализация и снимок. Контракт `search`/`open`/`read`/
`extract` для модели не изменится. Сырой HTML рендера в долгую память не
попадёт.

## 9. Файлы

- `packages/plugin_web_core/lib/src/web_plugin.dart` — инструменты.
- `packages/plugin_web_core/lib/src/fetch/page_fetcher.dart` — загрузка,
  редиректы, кодировка, robots.txt.
- `packages/plugin_web_core/lib/src/fetch/page_extractor.dart` — очистка,
  метаданные, режимы.
- `packages/plugin_web_core/lib/src/fetch/markdown_writer.dart` — DOM →
  Markdown и оглавление.
- `packages/plugin_web_core/lib/src/page_store.dart` — снимки и LRU/TTL.
- `packages/plugin_web_core/lib/src/search/` — Brave, Tavily, SearXNG.
- `packages/plugin_web/lib/plugin_web.dart` — экран настроек.
- `packages/pw_agent/lib/agent/plugins/plugin_tool_source.dart` — HTTP-мост
  и проверка адреса.
- `packages/pw_agent/lib/agent/context/context_builder.dart` — пометка
  вывода плагинов как недоверенного.

## 10. Ограничения

- Нет JavaScript-рендера: страница, которой нужен JS, вернёт
  `page_requires_javascript`.
- Нет поддержки восточноевропейских кодировок кроме UTF-8/latin1: Dart не
  содержит windows-1251. При необходимости добавляется отдельный декодер.
- Нет PDF, офисных документов и изображений.
- Снимки живут только в памяти процесса; после перезапуска страницу нужно
  открыть заново.
- Кэш не сохраняется на диск, ручной очистки в UI нет: TTL и LRU
  достаточно для первой версии.
