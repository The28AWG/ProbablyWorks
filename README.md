# ProbablyWorks

Настольный ИИ-агент, который выполняет задачи на вашем компьютере или SSH-сервере. Опишите задачу,
а агент сам прочитает файлы, запустит команды и внесёт изменения. Рискованные действия подтверждаете вы,
а ход работы видно в чате.

Модели работают через [OpenRouter](https://openrouter.ai), сам агент и все инструменты — локально.

## Возможности

- **Хосты:** этот компьютер (всегда есть) и SSH-серверы. Проверка подключения, задержка,
  заметки, рабочая папка и оболочка по умолчанию для каждого хоста.
- **Инструменты агента:** информация о хосте, список и чтение файлов, поиск (`grep`, `which`),
  запись и правка файлов, запуск команд, в том числе фоновых, поиск по истории чата,
  состояние задачи (цель, план, закреплённые факты) с ревизиями.
- **Политика исполнения:** режим *Ask* (подтверждать каждое действие) или *Авто-подтверждение* (`yolo`).
  Эскалация прав запрещена в обоих режимах.
  Команды классифицируются: эскалация прав (`sudo`, `su`, `doas` и т.п.) запрещена всегда,
  пайпы, редиректы и `eval` требуют подтверждения. Denylist — дополнительная страховка, а не граница безопасности.
- **Очередь ввода:** во время работы агента новые сообщения ставятся в очередь. Их можно
  отправить сразу (прервав текущий шаг), отредактировать или удалить.
- **Контекст и сжатие:** история собирается заново на каждый шаг. Старая часть сворачивается
  в сводку при приближении к лимиту окна модели, по росту числа результатов инструментов
  или вручную. Полный транскрипт в базе не удаляется.
- **Доверие к workspace:** `AGENTS.md` и skills из папки проекта попадают в контекст только после
  подтверждения пользователя. Вывод команд и файлы передаются модели как недоверенные данные.
- **Безопасность записи:** перед перезаписью файла создаётся копия `<файл>.pw-bak-<id запуска>`,
  в карточке approve показывается diff.
- **Секреты:** ключ OpenRouter и пароли/passphrase SSH хранятся в защищённом хранилище ОС.
  Значения маскируются в результатах инструментов, вложениях, сводках и логах приложения.
- **SSH:** проверка отпечатка ключа хоста при первом подключении и блокировка при его смене,
  аутентификация по ключу, паролю и keyboard-interactive.
- **Интерфейс:** адаптивная раскладка (широкое окно — список и чат рядом, среднее — рейл и drawer,
  узкое — стек), выбор модели с поиском, фильтром по tool calling и закреплёнными моделями,
  статус-строка с текущим шагом агента, уведомления о запросах подтверждения.
- **Языки:** русский и английский, переключаются в настройках.

## Требования

- Flutter SDK, совместимый с `sdk: ^3.13.7` из `pubspec.yaml`.
- Для сборки под Linux: набор зависимостей Flutter desktop (GTK 3, cmake, ninja и т.д.).
  Команда `flutter doctor` покажет, что не хватает.
- Для уведомлений на Linux: `notify-send` (пакет `libnotify-bin`).
- Ключ OpenRouter.
- Для работы с SSH-хостами — доступ к серверу по SSH.

## Установка и запуск

Пакет `openrouter` объявлен в `pubspec.yaml` как git-зависимость на тег `dist-v1.0.1`. Для разработки
файл `pubspec_overrides.yaml` (не коммитится) подменяет её локальной копией `../openrouter`, поэтому её
репозиторий должен лежать рядом с этим проектом. Freezed- и json-файлы пакета не лежат в репозитории, их
генерирует сам пакет, поэтому перед первой сборкой запустите `build_runner` в нём. Чтобы собрать без локальной
копии, удалите `pubspec_overrides.yaml`: pub возьмёт пакет из git-тега.

```bash
ls ..            # должна быть папка openrouter рядом с ProbablyWorks
(cd ../openrouter && dart run build_runner build --delete-conflicting-outputs)
flutter pub get
flutter gen-l10n   # обычно выполняется сам при сборке
dart run build_runner build --delete-conflicting-outputs
flutter run -d linux
```

`build_runner` генерирует код DI (`injectable`), маршрутов (`auto_route`) и базы данных (`drift`).
После изменения аннотаций или таблиц его нужно запустить заново.

Локализация: строки хранятся в `lib/l10n/app_en.arb` (шаблон) и `lib/l10n/app_ru.arb`.
Dart-файлы с переводами генерируются командой `flutter gen-l10n`, руками их не правят.

## Первый запуск

1. Откройте мастер и введите ключ OpenRouter. Приложение проверит его запросом списка моделей;
   неработающий ключ не сохраняется.
2. Выберите модель по умолчанию (нужна поддержка tool calling).
3. При желании укажите рабочую папку на этом компьютере.
4. При желании добавьте SSH-хост в разделе *Hosts*.
5. Создайте первый чат. Выберите хост, модель и политику, затем опишите задачу.

Пока ключ не сохранён, все экраны, кроме мастера, закрыты: `ApiKeyGuard` возвращает на онбординг.

## Структура проекта

Проект построен по принципу clean architecture с группировкой по функциям (feature-first).
Состояние UI — BLoC/Cubit, зависимости — `get_it` + `injectable`.

```
lib/
  app/        # запуск, DI, маршруты, тема, локализация, guards
  core/       # база (drift), настройки, хосты, секреты, логи, утилиты
  agent/      # ядро агента: цикл, контекст, инструменты, политика, exec, состояние
  host/       # исполнение команд на хосте: local и SSH, управление процессами
  providers/  # порт LLM и адаптер OpenRouter
  features/   # экраны и блоки: chat, chats, hosts, settings, onboarding, workspace, models
  l10n/       # ARB и сгенерированные строки
```

Ключевые компоненты:

- `agent/loop/chat_session.dart` — ход агента одного чата: очередь, шаги модели и инструментов, Stop.
- `agent/loop/agent_hub.dart` — точка входа агента, по одной сессии на чат; сессии живут, пока работает приложение.
- `agent/context/` — сборка контекста (`ContextBuilder`) и сжатие истории (`ContextCompactor`).
- `agent/policy/` — классификатор команд и политика Ask/Yolo.
- `agent/state/` — ревизии состояния задачи: при каждом сообщении пользователя текущая ревизия запечатывается.
- `host/` — `HostRuntime` для local и SSH, kill группы процессов и дерева детей.

## Данные и файлы

- База: `probably_works.db` (SQLite через drift) в папке поддержки приложения, подпапка `ProbablyWorks`.
  Схема версионируется через `schemaVersion`, миграции — в `app_database.dart`.
- Логи команд: во время выполнения пишутся в файлы, после завершения сжимаются в базу
  (голова и хвост по лимиту), файл удаляется.
- Журнал приложения: с ротацией и маскировкой секретов.
- Один экземпляр: вторая копия не открывает базу и показывает сообщение.

Лимиты и таймауты (размер вывода, параллельные команды на хост, таймаут SSH, число шагов агента,
лимиты вложений) задаются в *Settings* в формате JSON.

## Тесты

```bash
flutter test
```

Юнит-тесты не требуют внешних сервисов. Интеграционные SSH-тесты запускаются на throwaway-сервере
`linuxserver/openssh-server` (пользователь `pwtest`, пароль `pwtest123`):

```bash
docker run -d --name pw-sshd -p 2222:2222 \
  -e USER_NAME=pwtest -e USER_PASSWORD=pwtest123 -e PASSWORD_ACCESS=true \
  linuxserver/openssh-server:latest
PW_SSH_PORT=2222 flutter test test/host/ssh_host_runtime_test.dart
docker rm -f pw-sshd
```

Без `PW_SSH_PORT` эти тесты пропускаются.

Проверка кода:

```bash
dart analyze lib test
```

```bash
flutter build linux --release
```

Приложение нацелено на настольные платформы (Linux, macOS, Windows); остальные папки платформ в проекте
созданы стандартным шаблоном Flutter.

## Коммиты

Формат — Conventional Commits: `тип(область): описание`. Тип на английском, описание и тело на русском.
Шаблон лежит в `.gitmessage`. Подключите его один раз в клоне:

```bash
git config commit.template .gitmessage
```

Подробности и список типов и областей — в комментариях `.gitmessage`.

## Безопасность

- Агент выполняет команды на машине пользователя. Используйте режим Ask, если не уверены в задаче.
- Ключи и пароли не попадают в базу и логи в открытом виде.
- Эскалация прав (`sudo` и аналоги) запрещена на уровне политики, а не настраивается.
- Файлы из репозитория (`AGENTS.md`, skills) не могут переопределить политику безопасности.
