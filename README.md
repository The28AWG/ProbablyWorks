# ProbablyWorks

Настольный ИИ-агент, который выполняет задачи на вашем компьютере или SSH-сервере. Опишите задачу,
а агент сам прочитает файлы, запустит команды и внесёт изменения. Рискованные действия подтверждаете вы,
а ход работы видно в чате.

Модели работают через [OpenRouter](https://openrouter.ai), сам агент и все инструменты — локально.

## Возможности

- **Хосты:** этот компьютер (всегда есть) и SSH-серверы. Проверка подключения, задержка,
  заметки, рабочая папка и оболочка по умолчанию для каждого хоста.
  Виртуальный Host — отдельная среда с оболочкой-подмножеством bash и без терминала:
  состояние не сохраняется между `run_command`, фоновый запуск запрещён.
  Состав языка и известные расхождения — в [docs/shell.md](docs/shell.md).
  Слои файловой системы — в [docs/virtual-fs.md](docs/virtual-fs.md).
- **Инструменты агента:** информация о хосте, список, чтение, запись, правка,
  применение unified diff, удаление, перемещение и копирование файлов, создание
  каталогов, `stat`, поиск по содержимому (`grep`) и по именам файлов (`glob`),
  запуск команд, в том числе фоновых, с stdin, таймаутом и вводом в живой
  терминал, чтение вывода запусков и их остановка, поиск по истории чата,
  состояние задачи (цель, план, закреплённые факты) с ревизиями.
- **Политика исполнения:** режим *Ask* (подтверждать каждое действие) или *Авто-подтверждение* (`yolo`).
  Перед запуском команда разбирается пакетом [command_shield](https://pub.dev/packages/command_shield)
  (синтаксис bash): возможности, детекторы и вердикт, без выполнения.
  Эскалация прав запрещена всегда. Критические команды — уничтожение корня ФС или системного каталога,
  запись на блочное устройство, скачивание с немедленным запуском — запрещены даже в режиме
  авто-подтверждения. Пайпы, редиректы, подстановки и любые изменения требуют подтверждения в режиме Ask.
  Denylist — дополнительная страховка поверх разбора.
  Уровни категорий, отдельных команд и их аргументов задаются в настройках;
  более строгий из уровня и разбора побеждает, жёсткий пол настройкой не опускается.
- **Очередь ввода:** во время работы агента новые сообщения ставятся в очередь. Их можно
  отправить сразу (прервав текущий шаг), отредактировать или удалить.
- **Повтор и копирование:** последний ответ можно сгенерировать заново — с тем же
  неявным предложением откатить изменения файлов, что и при правке сообщения.
  Чат можно продублировать целиком или до любого завершённого ответа; файлы
  на хосте не копируются.
- **Карточки ожидания:** подтверждение и вопрос агента остаются, пока нет явного ответа
  (в том числе отказа или остановки хода). Закрытие приложения ответ не записывает:
  карточка снова появляется при открытии этого чата, и ход продолжается с этого места.
- **Контекст и сжатие:** история собирается заново на каждый шаг. Старая часть сворачивается
  в сводку при приближении к лимиту окна модели, по росту числа результатов инструментов
  или вручную. Полный транскрипт в базе не удаляется.
- **Доверие к workspace:** `AGENTS.md` и skills из папки проекта попадают в контекст только после
  подтверждения пользователя. Вывод команд и файлы передаются модели как недоверенные данные.
- **Проекты:** общая память, доверие и профиль политики принадлежат паре «хост + выбранная папка».
  Чат без папки не входит в домашний проект: факты и `~/AGENTS.md` не становятся общими для всех
  таких чатов. Команды при этом выполняются в папке хоста или в домашнем каталоге.
- **Безопасность записи:** перед перезаписью файла снимок сохраняется в хранилище данных
  приложения; при правке или укорочении истории чата можно восстановить файлы на хосте
  (как в Cursor). Бэкап для атомарной записи не лежит рядом с исходным файлом.
  В карточке approve показывается diff.
- **Секреты:** ключ OpenRouter и пароли/passphrase SSH хранятся в защищённом хранилище ОС.
  Значения маскируются в результатах инструментов, вложениях, сводках и логах приложения.
- **SSH:** проверка отпечатка ключа хоста при первом подключении и блокировка при его смене,
  аутентификация по ключу, паролю и keyboard-interactive.
- **Интерфейс:** адаптивная раскладка (широкое окно — список и чат рядом, среднее — рейл и drawer,
  узкое — стек), выбор модели с поиском, фильтром по tool calling и закреплёнными моделями,
  статус-строка с текущим шагом агента, системные уведомления о запросах подтверждения, вопросах агента,
  завершении, ошибке, лимите шагов и фоновых командах (только когда окно приложения не в фокусе).
  В заголовке уведомления — действие и название чата, в тексте — что нужно сделать.
- **Языки:** русский и английский, переключаются в настройках.
- **Тема:** системная, светлая или тёмная, выбирается в настройках.

## Требования

- Flutter SDK, совместимый с `sdk: ^3.13.7` из `pubspec.yaml`.
- Для сборки под Linux: набор зависимостей Flutter desktop (GTK 3, cmake, ninja и т.д.).
  Команда `flutter doctor` покажет, что не хватает.
- Для уведомлений на Linux: `notify-send` (пакет `libnotify-bin`).
- Локальный PTY (пакет `portable_pty`, нативная Rust-библиотека) собирается одним из способов:
  - Rust-тулчейн версии 1.92 или новее (нужен для hook-а пакета `native_toolchain_rust`);
  - либо предсобранная библиотека, которую hook пакета скачивает с GitHub Releases и проверяет по хешу из манифеста
    пакета. Для этого нужен доступ в интернет при первой сборке.
  Локальный PTY проверен на Linux. Android и macOS используют тот же POSIX-путь, но не собраны и не проверены
  на этой машине. Windows в этой версии не поддерживается: неблокирующий режим для ConPTY не реализован, и
  локальный Host на Windows не запустит команду (SSH-хосты работают). На iOS локального Host нет.
- Ключ OpenRouter.
- Для работы с SSH-хостами — доступ к серверу по SSH.

## Установка и запуск

```bash
flutter pub get
flutter gen-l10n   # обычно выполняется сам при сборке
dart run build_runner build --delete-conflicting-outputs
(cd packages/pw_agent && dart run build_runner build --delete-conflicting-outputs)
flutter run -d linux
```

`build_runner` генерирует код DI (`injectable`), маршрутов (`auto_route`) и базы данных (`drift`).
После изменения аннотаций или таблиц его нужно запустить заново.

Локализация: строки хранятся в `lib/l10n/app_en.arb` (шаблон) и `lib/l10n/app_ru.arb`.
Dart-файлы с переводами генерируются командой `flutter gen-l10n`, руками их не правят.

## Первый запуск

1. Откройте мастер и введите ключ OpenRouter. Приложение проверит его запросом сведений о ключе;
   неработающий ключ не сохраняется.
2. Выберите модель по умолчанию (нужна поддержка tool calling).
3. При желании укажите рабочую папку на этом компьютере.
4. При желании добавьте SSH-хост в разделе *Hosts*.
5. Создайте первый чат. Выберите хост, модель и политику, затем опишите задачу.

Пока ключ не сохранён, все экраны, кроме мастера, закрыты: `ApiKeyGuard` возвращает на онбординг.

## Структура проекта

Проект построен по принципу clean architecture с группировкой по функциям (feature-first).
Состояние UI — BLoC/Cubit, зависимости — `get_it` + `injectable`.

```
packages/
  pw_agent/      # агент, БД, Host и провайдеры без Flutter
  pw_client/     # HTTP/SSE клиент AgentApi для удалённых профилей
  pw_server/     # HTTP API и headless-запуск поверх pw_agent
  virtual_git/   # git поверх файловой системы виртуального хоста и по HTTPS
  virtual_host/  # ядро виртуального хоста: файловая система, оболочка, апплеты
lib/
  app/        # запуск, DI, маршруты, тема, локализация, guards
    ui/       # собственные виджеты (AppCard, ActionCard, ConfirmDialog, ...), см. docs/ui/WIDGET_BOOK.md
  core/       # база (drift), настройки, хосты, секреты, логи, утилиты
  agent/      # ядро агента: цикл, контекст, инструменты, политика, exec, состояние
  host/       # исполнение команд: local, SSH и адаптер виртуального хоста
  providers/  # порт LLM и адаптер OpenRouter (структурные и текстовые tool call)
  features/   # экраны и блоки: chat, chats, hosts, settings, onboarding, workspace, models
  l10n/       # ARB и сгенерированные строки
```

Ключевые компоненты:

- `agent/loop/chat_session.dart` — ход агента одного чата: очередь, шаги модели и инструментов, Stop.
- `agent/loop/tool_scheduler.dart` — параллельный запуск инструментов одного шага: независимые вызовы вместе, конфликт по каноническому пути и состоянию сохраняет порядок модели. `~` и симлинки сверяет Host, команда занимает хост целиком, даже если классификатор счёл её чтением. После перезапуска шаг продолжается сразу: прерванный процесс в ленту возвращается как результат и заново не запускается, вызов без карточки идёт, как только закрыты его зависимости. Карточку подтверждения или вопроса регистрирует только открытие чата.
- `agent/loop/agent_hub.dart` — точка входа агента, по одной сессии на чат; сессии живут, пока работает приложение.
- `agent/context/` — сборка контекста (`ContextBuilder`) и сжатие истории (`ContextCompactor`).
- `agent/policy/` — классификатор команд и политика Ask/Yolo.
- `agent/state/` — ревизии состояния задачи: при каждом сообщении пользователя текущая ревизия запечатывается.
- `host/` — `HostRuntime` для local и SSH: служебные команды через pipe (`run`), команды агента в PTY (`openTerminal`), kill группы процессов и дерева детей.

## Данные и файлы

- База: `probably_works.db` (SQLite через drift) в папке поддержки приложения, подпапка `ProbablyWorks`.
  Схема версионируется через `schemaVersion`, миграции — в `app_database.dart`.
- Логи команд: во время выполнения пишутся в файлы, после завершения сжимаются в базу
  (голова и хвост по лимиту), файл удаляется.
- Журнал приложения: с ротацией и маскировкой секретов.
- Один экземпляр: вторая копия не открывает базу и показывает сообщение.

Лимиты и таймауты (размер вывода, параллельные команды на хост, таймаут SSH, число шагов агента,
лимиты вложений) задаются в *Settings* в формате JSON.

## Тесты

```bash
flutter test
(cd packages/pw_agent && dart test)
(cd packages/pw_client && dart test)
(cd packages/pw_server && dart test)
(cd packages/virtual_host && dart test)
(cd packages/virtual_git && dart test)
```

Юнит-тесты не требуют внешних сервисов. Интеграционные SSH-тесты запускаются на throwaway-сервере
`linuxserver/openssh-server` (пользователь `pwtest`, пароль `pwtest123`):

```bash
docker run -d --name pw-sshd -p 2222:2222 \
  -e USER_NAME=pwtest -e USER_PASSWORD=pwtest123 -e PASSWORD_ACCESS=true \
  linuxserver/openssh-server:latest
PW_SSH_PORT=2222 flutter test test/host/ssh_host_runtime_test.dart
docker rm -f pw-sshd
```

Без `PW_SSH_PORT` эти тесты пропускаются.

Проверка кода:

```bash
dart analyze lib test
```

## Коммиты

Формат — Conventional Commits: `тип(область): описание`. Тип на английском, описание и тело на русском.
Шаблон лежит в `.gitmessage`. Подключите его один раз в клоне:

```bash
git config commit.template .gitmessage
```

Подробности и список типов и областей — в комментариях `.gitmessage`.

## Безопасность

- Агент выполняет команды на машине пользователя. Используйте режим Ask, если не уверены в задаче.
- Ключи и пароли не попадают в базу и логи в открытом виде.
- Эскалация прав и критические команды запрещены разбором `command_shield`, а не настройкой.
  В настройках можно поднять или опустить уровень категории, команды и аргумента,
  но не ниже того, что уже запретил разбор. Разбор снижает риск и не заменяет
  отдельного пользователя и режим Ask.
- Файлы из репозитория (`AGENTS.md`, skills) не могут переопределить политику безопасности.
