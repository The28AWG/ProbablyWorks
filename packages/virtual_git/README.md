# virtual_git

Git поверх файловой системы виртуального хоста. Репозиторий, индекс и объекты
живут в `VirtualFs`. Сеть — только HTTP и HTTPS через `package:http`.
Пакет не знает про приложение, базу и `SecretStore`. Это чистый Dart, без Flutter.

В стандартный набор апплетов `virtual_host` git не входит. Его регистрирует
вызывающий код рядом со `standardApplets`.

Публичный вход — `package:virtual_git/virtual_git.dart`.

Поведение команд перенесено из [git_core](https://github.com/Atrac613/git_core)
(MIT, текст лицензии — `THIRD_PARTY_LICENSE`). Зависимостью пакет не подключается:
исходник импортирует `dart:io` и SSH.

## Апплет

```dart
import 'package:virtual_git/virtual_git.dart';
import 'package:virtual_host/virtual_host.dart';

final applets = AppletRegistry([
  for (final name in standardApplets.names) standardApplets.lookup(name)!,
  const GitApplet(),
]);
final fs = VirtualFs(
  InMemoryVfsStore(),
  snapshot: OsSnapshot(
    profile: const VirtualProfile(),
    names: applets.names,
  ),
);
final interpreter = ShellInterpreter(
  fs: fs,
  applets: applets,
  profile: const VirtualProfile(),
);
final events = await interpreter.run('git init', cwd: '/work').toList();
```

Имя `git` должно быть и в реестре, и в снимке `/bin`: иначе `which git` и
`test -x /bin/git` расходятся. Неизвестная подкоманда пишет в stderr и
завершается с кодом 1. Какие команды git разобраны, а какие запрещены,
перечислено в отчёте ниже.

Опции разбираются как у git: `--name`, `--name=value`, `-s`, `-svalue`, `--`.
До команды действуют `-C`, `-c key=value`, `--bare`, `--version` и `--help`.
Неизвестная опция — код 129 и `error: unknown option`. Ветка по умолчанию у
`init` — `main` (`-b` её меняет, `--object-format=sha256` пишет маркер
формата). `--depth` для `file://` и HTTP обрезает историю и пишет
`.git/shallow`. Предупреждение `warning: --depth is ignored in local clones;
use file:// instead.` относится только к обычному пути каталога: git сам
игнорирует глубину при локальном клоне и предлагает `file://`. Это не отказ
в shallow-копировании. `--filter=blob:none`
не копирует blob и оставляет promisor-метку. Если сервер объявляет
`git-upload-pack`, объекты читаются одним pack через него: путь
`objects/ab/хеш` остаётся только для dumb HTTP. Pack, который помещается в
лимит файла, пишется в `.git/objects/pack` рядом с loose-объектами. SSH, хуки,
credential helper, gpg, mergetool, pager и редактор по-прежнему недоступны:
в `lib/` нет процессов и сокетов.

## Автор и заголовок

Апплет читает окружение оболочки, а не `.git/config`:

- `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_COMMITTER_NAME`,
  `GIT_COMMITTER_EMAIL` — подпись коммита. Если их нет, имя и почта берутся
  из пользователя и хоста `VirtualProfile`.
- `GIT_HTTP_EXTRA_HEADER` — одна строка вида `Authorization: Bearer …` на
  `clone`, `fetch`, `pull` и `push`. В конфиг репозитория она не пишется.

Карту задаёт `VirtualProfile.environment`. Встроенные имена (`PATH`, `HOME`
и остальные) она не перезаписывает.

## Библиотека

`GitRepository` работает только после `bindGitIo`. Привязка общая на изолят:
перед вызовом её включают, после — снимают. Апплет делает это сам.

```dart
bindGitIo(fs, cwd: '/work');
try {
  final repository = GitRepository.workTree('/work/repo');
  await repository.status();
} finally {
  clearGitIo();
}
```

Свой транспорт подставляют вторым аргументом `GitApplet` или через `bindGitIo`.
Без него запросы идут в `PackageGitHttp`. Относительный remote без схемы — это
другой путь в той же `VirtualFs`, не каталог машины.

## Чего нет

- SSH, `ssh://` и `git@host`.
- Запись на диск машины, процессы и сокеты. Сторож `test/guard_no_io_test.dart`
  пускает в `lib/` только `package:http`.
- Pack больше лимита одного файла. Он не записывается и не обрезается:
  операция завершается ошибкой.
- Credential helper, который запускает процесс, и linked worktree с `gitdir`
  вне этой `VirtualFs`.

## Отчёт: команды git 2.53

Снимок снят с git 2.53.0. Отметка стоит у команды целиком.

- ✅ реализована — апплет эту подкоманду разбирает. Совпадение каждой опции
  эта отметка не обещает.
- ⬜ не реализована — у git команда есть, и ограничения пакета ей не мешают.
- 🚫 запрещена — команде нужен графический интерфейс, внешний процесс, сокет
  кроме `package:http`, SSH, GPG, хуки, credential helper, запись на диск
  машины или чужая система контроля версий.

Уточнения к реализованным командам (где поведение отличается от полного git
или требует пояснения) — в [docs/command_notes.md](docs/command_notes.md).

`git` и `git --help` печатают только основные команды. `ls-remote` там нет:
она лежит среди низкоуровневых команд чтения. Полный список с коротким
описанием даёт `git help -a`. Справка по одной команде:

```bash
git help ls-remote
man git-ls-remote
git ls-remote -h
```

Первые две команды открывают полное описание. Третья печатает только короткие
опции и завершается с кодом 129. Имена, которые git готов выполнить, включая
служебные, печатает `git --list-cmds=main`. Каталог этих программ показывает
`git --exec-path`.

`git help -a` называет 151 команду и отдельно 19 страниц справки. Это не
команды: `attributes`, `cli`, `hooks`, `ignore`, `mailmap`, `modules`,
`repository-layout`, `revisions`, `format-bundle`, `format-chunk`,
`format-commit-graph`, `format-index`, `format-pack`, `format-signature`,
`protocol-capabilities`, `protocol-common`, `protocol-http`, `protocol-pack`,
`protocol-v2`. Их открывает тот же `git help <имя>`.

Из 151 команды реализовано 68, не реализовано 55, запрещено 28. Ещё 32
служебных имени есть в `git --list-cmds=main` и отдельной строкой в
`git help -a` не показаны: из них 13 не реализованы и 19 запрещены.
`git-quick-stats` на этой машине тоже попадает в `--list-cmds=main`, но это
пакет Debian, не git 2.53. В `--exec-path` лежат ещё shell-библиотеки
`mergetool--lib` и `sh-prompt`: командами они не являются.

В пакете дополнительно есть `lfs`. В git 2.53 такой команды нет: это фильтр
Git LFS, и здесь он работает внутри процесса.

- `merge-recursive` — рекурсивная стратегия слияния. ⬜
- `merge-recursive-ours` — рекурсивная стратегия с предпочтением наших изменений. ⬜
- `merge-recursive-theirs` — рекурсивная стратегия с предпочтением чужих изменений. ⬜
- `merge-resolve` — старая стратегия слияния через общее дерево. ⬜
- `merge-subtree` — стратегия слияния поддерева. ⬜
- `pickaxe` — служебное имя поиска изменений. `git pickaxe -h` печатает справку `blame`. ⬜
- `receive-pack` — принять объекты при push на стороне сервера. 🚫
- `remote-ext` — транспорт через внешнюю команду. 🚫
- `remote-fd` — транспорт через уже открытый файловый дескриптор. 🚫
- `remote-ftp` — remote-helper для FTP. 🚫
- `remote-ftps` — remote-helper для FTPS. 🚫
- `remote-http` — remote-helper для HTTP, отдельный процесс. 🚫 HTTP-транспорт `clone`, `fetch` и `push` реализован внутри процесса.
- `remote-https` — remote-helper для HTTPS, отдельный процесс. 🚫 HTTPS идёт тем же внутрипроцессным транспортом.
- `sh-i18n--envsubst` — подстановка строк для shell-скриптов Git. 🚫
- `shell` — ограниченная оболочка входа по SSH. 🚫
- `stage` — старое имя `add`. ⬜
- `submodule--helper` — служебная часть `submodule`. ⬜
- `subtree` — влить поддерево чужого репозитория или вырезать каталог в отдельную историю. ⬜
- `upload-archive` — отдать архив по запросу серверной стороны. 🚫
- `upload-archive--writer` — записать архив для `upload-archive`. 🚫
- `upload-pack` — отдать pack по запросу `fetch` на стороне сервера. 🚫
- `web--browse` — открыть адрес в браузере. 🚫
